# v0.1 Implementation Design

## Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Project layout | `cmd/git-zhi/` + `internal/` | Standard Go convention for single-binary projects |
| CLI framework | Cobra | Matches pvm patterns; factory functions per command group |
| Git access | go-git (pure Go) | No runtime git binary dependency for ref operations |
| UUID library | gofrs/uuid | UUIDv7 support for time-ordered, collision-free issue IDs |
| YAML library | goccy/go-yaml | Fast parsing, good error messages for frontmatter and config |
| Interactivity | Non-interactive first | stdin/pipe + `--format json` before `$EDITOR` support |
| Decomposition | Vertical slices by command | Each issue delivers one working command end-to-end |

## Package Structure

```
git-zhi/
  cmd/git-zhi/main.go       # entry point
  internal/
    cli/                       # Cobra commands + App struct
    storage/                   # go-git ref CRUD (write entity, read entity, list refs)
    issue/                     # issue domain model (parse, marshal, state machine)
    milestone/                 # milestone domain model (pure YAML)
    graph/                     # DAG construction, invariants, critical chain
    telemetry/                 # MPG, speed, buffer, fever chart
    config/                    # chain configuration
    resolve/                   # ref argument resolution (HEAD, tag, UUID prefix, title)
  docs/
  go.mod
```

## Storage Layer

Each issue and milestone gets its own git ref under `refs/zhi/`. Each ref's commit history is an append-only event log. Current state is the latest commit's blob.

**Write path** (e.g., `issue add`):
1. Create blob containing issue markdown
2. Create tree with one entry: `issue.md` -> blob
3. Create commit pointing at tree (parent = previous commit on ref, or none for first)
4. Update ref to new commit

**Read path** (e.g., `issue show`):
1. Resolve ref to commit
2. Read tree from commit
3. Read blob from tree entry
4. Parse markdown into domain object

The `Store` exposes four operations:

```go
type Store struct{ repo *git.Repository }

func (s *Store) WriteEntity(refPath, filename string, content []byte, message string) error
func (s *Store) ReadEntity(refPath, filename string) ([]byte, error)
func (s *Store) ListRefs(prefix string) ([]string, error)
func (s *Store) RefExists(refPath string) bool
```

## Issue Domain Model

Issues are markdown files with YAML frontmatter. The `issue` package owns parsing, validation, and serialization.

```go
type Issue struct {
    ID        uuid.UUID
    Title     string
    State     State          // pending | in-progress | done | cancelled
    Milestone string
    BlockedBy []uuid.UUID
    Blocks    []uuid.UUID
    Created   time.Time
    Updated   time.Time
    Sessions  []Session
    Body      string         // raw markdown (Prerequisites, Context, AC sections)
}
```

The `Body` field stores raw markdown. Structured context extraction (for `--format json`) is a presentation concern handled separately.

State transitions follow a validated state machine:
- pending -> in-progress, cancelled
- in-progress -> done, cancelled
- cancelled -> pending (stdin editing only, not via `--state` flag)

## CLI Structure

Cobra root command with subcommand groups. Dependencies flow through an `App` struct created in `PersistentPreRunE` and attached to the command context.

```go
type App struct {
    Store *storage.Store
    Repo  *git.Repository
}
```

Commands: `list`, `config`, `next` (top-level); `issue add|list|show|edit`; `milestone add|list|show|edit`.

All commands that produce output support `--format json` via a flag on the root command.

## Graph Operations

The `graph` package reconstructs the DAG from a set of loaded issues and enforces five invariants:
1. Acyclic (DFS cycle detection on every `AddEdge`)
2. Referential integrity (no dangling dependency edges)
3. Done/cancelled issues cannot gain new incoming dependencies
4. Split issues inherit downstream dependencies
5. Cancelled issues reconnect the graph

Critical chain = longest path through non-done/non-cancelled issues, computed via topological sort + dynamic programming (linear time).

`Head()` returns the in-progress issue if one exists, otherwise the next issue on the critical chain with the most downstream dependencies.

## Telemetry

Stateless computation over completed issue data. No persistent telemetry state.

- **MPG**: total commits across measurement windows / completed issue count
- **Speed**: completed issues / calendar weeks elapsed since first start
- **Buffer**: starts at 50% of milestone issue count; refined by MPG variance and speed changes
- **Fever chart**: GREEN (buffer burn < progress), YELLOW (roughly equal), RED (buffer burn > progress + 20 points)
- **Time-in-chain**: active measurement time / total calendar time

## Lazy Init, Config & Sync

**Lazy init**: first mutating command checks for `refs/zhi/_/config` and bootstraps if absent. Creates config, default milestone, and refspecs. Read-only commands skip init.

**Config**: YAML blob at `refs/zhi/_/config`. Two fields for v0.1: `version` and `default_milestone`.

**Sync**: lazy init adds fetch/push refspecs for `refs/zhi/*` to `.git/config` via go-git's config API. Deferred if no remote exists.

## Tags & Resolution

Tags are lightweight refs: `refs/zhi/_/tags/<name>` points at an entity ref. Mutable pointers, no commit chain.

Ref resolution order for any `<ref>` argument:
1. "HEAD" or empty -> in-progress issue, or next on critical chain
2. Tag name -> `refs/zhi/_/tags/<input>`
3. UUID prefix -> scan issue refs for unique match
4. Title substring -> scan issues for unambiguous match
5. Error with candidates if ambiguous

## Issue Decomposition

Ten issues, each session-sized. Dependencies flow downward.

| # | Title | Delivers | Depends on |
|---|-------|----------|------------|
| 1 | Bootstrap project skeleton | go.mod, package dirs, Cobra root, compiles and runs | — |
| 2 | `issue add` | Storage layer, issue model, UUIDv7, lazy init, default milestone, stdin input | 1 |
| 3 | `issue show` | Read path, UUID prefix resolution, human + JSON output, body section parsing | 2 |
| 4 | `issue list` | Collection query, creation-time sort, `--milestone`/`--state` filters, JSON output | 2 |
| 5 | `issue edit --state` | State machine, measurement bookmarks, session tracking | 2 |
| 6 | `issue edit` (remaining) | `--before/after`, `--block/unblock`, `--milestone`, `--tag/untag`, `--split`, `--merge`, `--purge`, stdin editing | 2 |
| 7 | Graph invariants & critical chain | DAG construction, cycle detection, invariant enforcement, critical chain, `Head()` | 5, 6 |
| 8 | Milestone commands | `milestone add/list/show/edit`, milestone model, fever chart display | 2 |
| 9 | `zhi list` + `zhi next` + `zhi config` | Topological sort, `--graph`/`--critical` modes, `next` alias, config read/write | 7 |
| 10 | Telemetry, sync & tags | MPG/speed/buffer computation, refspec config, tag CRUD, full resolution chain | 8, 9 |
