## Postmortem: Four Questions

### What worked?

1. **crochet:execute ran end-to-end for the first time.** The full outer
   loop executed: pick issue → start → Ralph Loop (TDD) → simplify →
   commit → close → sanbao gate → PAAD alignment → next issue → milestone
   complete → postmortem. Every step of the skill worked as designed.

2. **TDD via Ralph Loop produced clean code on first pass.** Issue 019d0891
   went RED → GREEN → simplify → commit in a single iteration. The
   simplifier found real issues (duplicated 3-call pattern, repoRootPath
   hoisting) that were fixed before the commit. PAAD alignment found zero
   issues.

3. **Sanbao gate analyst tiering worked correctly.** Both issues scored
   below all tier-2 thresholds (difficulty < 0.4, hotspots <= 2, no
   coupling, MPG <= 3). Tier-1 (alignment only) was the correct call —
   these were low-complexity changes.

4. **Per-issue hotspot scoping now works.** The v0.3.4 postmortem
   identified milestone-level hotspot scoping as a gap. v0.3.5 closed
   that gap: DifficultyEntry now includes HotspotCount and CouplingCount
   computed from each issue's sessions.

### What didn't work?

1. **Ralph Loop completion promise detection failed.** The `<promise>`
   tag was output correctly in 3 separate iterations but never detected
   by the stop hook. Root cause: `jq -rs` (slurp mode) fails when any
   JSONL transcript line contains unescaped control characters
   (U+0000-U+001F). Long conversations with tool output (git diffs,
   file reads) produce these invalid lines. Filed as
   [claude-plugins-official#760](https://github.com/anthropics/claude-plugins-official/issues/760).

2. **Issue creation for git-zhi requires stdin with YAML frontmatter.**
   Three failed attempts before getting the format right (`--body` flag
   doesn't exist, positional title requires stdin for body, apostrophes
   in heredocs cause shell escaping issues). The API is not intuitive
   for programmatic issue creation.

3. **Shadow work was high (70%).** Most of the investigation into the
   Ralph Loop failure was necessary but untracked. The git-zhi issue
   only captured the resolution, not the debugging process.

### What puzzles us?

1. **Why did the Ralph Loop continue despite jq failure?** The hook's
   error path (lines 119-126) removes the state file and exits 0, which
   should stop the loop. Yet the loop ran 4 iterations. Either the state
   file was recreated between hook invocations, or the hook's exit 0
   was not interpreted as "allow exit" by the system. This needs deeper
   investigation.

2. **The sanbao report doesn't include the new fields yet.** The
   installed binary predates the v0.3.5 changes, so the sanbao JSON
   output still shows the old DifficultyEntry format (no hotspot_count
   or coupling_count). The binary needs to be rebuilt and installed
   before the gate analyst can use per-issue hotspot data. Same
   chicken-and-egg problem as v0.3.3 and v0.3.4.

### What should we change?

1. **Rebuild and install after every code milestone.** This is the
   fourth time we've hit the stale-binary problem. Make it a hard step
   in crochet:execute Step 5 (milestone completion): rebuild, install,
   verify version string.

2. **Add a `--body` flag or simplify stdin format for `issue add`.**
   The current YAML-frontmatter-on-stdin approach is fragile for
   programmatic use. Consider accepting `--body "text"` as a flag.

3. **Track investigation time as shadow work explicitly.** When
   debugging takes significant time outside of issue execution, log it
   somehow — even a manual note helps the postmortem be more accurate.
